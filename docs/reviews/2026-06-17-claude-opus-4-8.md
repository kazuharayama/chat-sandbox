## 1. 総合評価

**評価: C (部分的に改善が必要)**

**理由**:
ドキュメントは直近の大規模なLLMプロバイダー刷新と音声機能の実装転換をほぼ反映していますが、複数の箇所で古い仕様が残存しており、特に以下の点で実装とズレがあります:
1. **PRD/architecture-flow.md**: Azure OpenAI記述が大幅に古い (実装は廃止済み)
2. **FC-voice.md**: WebRTC+aiortc+Azure Speech SDKを仕様としているが、実装はWhisper+Piper (ファイルベース)
3. **F0-agent-config.md**: vLLMサポートを記載しているが実装に存在しない
4. **デフォルトモデル名**: ドキュメント記載値と実際のseedデータがズレている

ただし、F0, FA, FB, FE要件の大枠は実装と整合しており、中核機能は正常です。

## 3. 重要な不足 (High)

### 3.1 デフォルトモデル情報の不正確さ
- **ドキュメント**: `F0-agent-config.md:48-49, 228-234` が `llama3.1:8b` / `gemma2:9b` / `gpt-4o(default)` を例示。
- **実装**: 実シードは `gemma2:2b`(デフォルト), `llama3.2:3b`, `claude (CLI)` (`agent_config_repository.py:110-116`, `config.py:9`)。
- **修正案**: 例を実シードに合わせ、「メモリ効率のため小規模モデルをデフォルト化。GPU環境では大規模モデルにも対応可」と補足。

### 3.2 requirements/README.md: Phase 4 が未実装方式
- **ドキュメント**: `README.md:81-84` が「Phase 4: WebRTC Voice対話」。だが同README:41 は「FC 完了 (Whisper+Piper)」。同一文書内で矛盾。
- **修正案**: Phase 4 を削除 or「将来構想」へ移動し、FC を「完了 (Whisper+Piper ファイルベース)」で統一。API表/DB表/リスクの WebRTC 記述も除去。

### 3.3 ER図: テーブル定義が実装と若干ズレ
- **ドキュメント**: `er-diagram.md` の knowledge_sources 定義に `is_enabled` 等が不足、routing_rules→agent_definitions のリレーションが不完全。
- **実コード**: `agent_config_repository.py:95-105`, `docker/postgres/init.sql`(チャット系のみ、agent-configはアプリ起動時 `_ensure_tables()` で作成)。
- **修正案**: knowledge_sources に `is_enabled BOOLEAN DEFAULT true` 追記、リレーション補完、「agent-config テーブルはアプリ管理」の注記追加。
