# Azure Front Door 導入メモ

現在の構成では nginx コンテナアプリが単一の入口となり、Azure Container Apps の標準 Ingress で公開しています。Azure Front Door を前段に置くと、グローバル負荷分散や WAF を追加でき、ゼロダウンタイムなブルーグリーン切替も柔軟になります。

## 採用するメリット
- **グローバルなエニーキャスト入口**: 世界中のエッジからユーザーを最寄りリージョンに誘導し、レイテンシを低減。
- **WAF / DDoS 緩和**: マネージドルールで OWASP Top 10 などを軽減し、Bot 保護やレート制限も設定可能。
- **SSL/TLS 終端と証明書管理**: Front Door 側で TLS を終端し、バックエンド (nginx) との通信を HTTPS で再暗号化するポリシーも設定可能。
- **ヘルスプローブとトラフィック制御**: バックエンドのヘルスチェック、優先度／重み付けによるフェイルオーバーや分散が可能。Container Apps の複数リビジョンやリージョン拡張と組み合わせやすい。
- **キャッシュ (Standard/Premium)**: 静的アセットをエッジでキャッシュしてフロントエンド応答を高速化。

## コストの考え方
Front Door は従量課金で、主に以下の要素があります。単価はリージョンや SKU により変わるため公式料金表を確認してください。
- **基本料金 (固定の時間課金)**: Standard/Premium で 1 時間あたりのベース料金が発生。
- **データ転送料 (アウトバウンド)**: インターネットへの応答データ転送に応じた料金。エッジからクライアントへの転送が課金対象。
- **ルール・WAF**: ルールセット数や WAF ポリシーに応じた追加料金が発生。Bot 保護を有効化すると別途従量課金。
- **リソース消費の間接コスト**: Front Door からバックエンド (nginx/Container Apps) へのオリジン転送も発生するため、バックエンド側の外部送信課金やスケールアウトにつながる場合があります。

ざっくり言えば「エッジ入口の固定費 + 転送量 + (WAF/ルール等のオプション)」がかかるため、月間トラフィックや必要なセキュリティ機能を見積もって判断します。

## このリポジトリで導入する場合のイメージ
1. **オリジングループ**: nginx Container App の外部 URL をバックエンドとして登録。将来的に複数リージョンへ展開するならバックエンドを追加し、優先度/重みで制御。
2. **カスタムドメイン & TLS**: Front Door にカスタムドメインを割り当て、托管証明書か自前証明書を使う。nginx 側も HTTPS 再暗号化を求める設定に変更。
3. **WAF ポリシー**: Standard/Premium WAF を作成し、Managed Rule Set を有効化。必要に応じてレート制限や Bot 保護を設定。
4. **監視**: Diagnostic Settings を使って Front Door のアクセスログ・WAF ログを Log Analytics に送信し、既存の ACR/Key Vault ログと統合。

## いつ選択すべきか
- グローバル利用や大規模トラフィックでレイテンシ・可用性を最適化したいとき。
- WAF や Bot 保護をマネージドで使いたいとき。
- CDN キャッシュで静的アセットをエッジ配信したいとき。

逆に、単一リージョンの小規模トラフィックであれば、Container Apps の Ingress + nginx だけの構成の方がコストは抑えやすいです。Front Door を導入するかは必要なセキュリティ・性能要件とトラフィック量から検討してください。
