# FF: モデル切替時の品質保証

| 項目 | 内容 |
|------|------|
| 優先度 | P1 |
| 複雑度 | L (2〜3週間) |
| 依存 | F0, FA, FE |

## 1. 目的

使用者がLLMモデルを切り替えても回答品質を落とさないようにする。モデルごとに最適なプロンプトは異なるため、(1) プロンプトをモデルに紐づけて切り替え時に最適なものが使われるようにし、(2) 切り替え前後の応答を素早く比較・評価して品質の劣化を検知できる状態にする。

## 2. ユーザーストーリー

1. 使用者として、モデルを切り替える前に、同じ質問を新旧モデルで並べて比較したい。品質が落ちないか確認してから切り替えられるように。
2. 使用者として、モデルを切り替えたら、そのモデル用に調整されたプロンプトが自動で使われてほしい。モデルごとに手直しせず済むように。
3. 開発者として、モデル（系統）ごとにプロンプトを用意・調整したい。各モデルの特性に合わせて品質を最適化できるように。
4. 開発者として、代表的な質問セットで新旧モデルの回答品質をスコア比較したい。切り替えによる劣化を客観的に検知できるように。

## 3. 受入基準

1. 同一の質問を2つのモデルに流し、両方の回答を並べて確認できること
2. モデルにプロンプトが紐づいている場合、そのモデル使用時に自動で適用されること
3. モデル（系統）ごとにプロンプトを用意・編集・保存できること
4. モデルにプロンプトが紐づいていない場合は、既定のプロンプトにフォールバックすること（切り替えで無設定にならない）
5. 評価用の質問セットを、指定したモデルで一括実行し、品質スコアを算出できること
6. 2モデルの評価スコアを比較し、劣化（スコア低下）を確認できること

## 4. 技術アプローチ（概要）

### 4.1 モデル別プロンプト

- プロンプトを「モデル（または系統）」に紐づけられるようにする。プロンプト選択時に、使用中のモデルに対応するものを優先し、無ければ既定にフォールバックする。
- 既存のプロンプトのバージョン管理の仕組みと両立させる。

### 4.2 2モデル並列比較（Context Lab 拡張）

- Context Lab に「モデルを指定して試す」機能と、同一入力を2モデルへ同時に流して結果を左右に並べる比較ビューを追加する。
- 検索・コンテキスト生成は共通のまま使い、生成の部分だけ2モデルに分岐する。

### 4.3 回帰検知（評価基盤の利用）

- 評価用の質問セットを指定モデルで一括実行し、スコア化して比較する。スコアリング手法と評価データの管理は FE の評価基盤を用いる。
- デフォルトモデルの切り替え前に、この比較結果を確認できるようにする。

## 5. 他フィーチャーとの関係

- FE（精度改善・運用基盤）: 評価データセットとスコアリング基盤は FE が担う。FF はそれを「モデル比較・切替時の回帰検知」に利用する（評価基盤は重複実装しない）。
- FA（Context Lab）: 2モデル並列比較の実行・表示は Context Lab を拡張して実現する。
- F0（エージェント設定基盤）: モデル・プロンプト・設定の管理（DB／設定画面）は F0 の基盤に乗る。モデル別プロンプトは F0 のプロンプト管理を拡張する形で追加する。
